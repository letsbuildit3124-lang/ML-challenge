# Validation vs Test Candidate Generation & Blocking Evaluation Report

## Executive Summary

This diagnostic report compares candidate generation behavior between the **Validation Dataset** and the **Test Dataset**. 

We analyze individual blocking method yield, candidate duplication rates, candidate count distribution per S1 entity, and target table block size explosion risks.

## 3. Method-by-Method Blocking Yield & Runtime Comparison

| Blocking Rule | Val Candidates | Val Yield (cands/S1) | Test Candidates | Test Yield (cands/S1) | Test Method Runtime (s) |
| :--- | :--- | :--- | :--- | :--- | :--- |

| **5. Postal PIN + CName4** | 17 | 0.007 | 4 | **0.002** | 0.007 s |
| **6. Phonetic Soundex + Num** | 5,015 | 2.006 | 9,428 | **3.771** | 0.033 s |
| **7. Transliteration CName** | 9,322 | 3.729 | 6,870 | 2.748 | 0.042 s |
| **Total Raw Candidates** | **25,411** | **10.164** | **25,947** | **10.379** | **0.247 s** |

### Key Observations:
1. **Phonetic Soundex Explosion**: `method_d_phonetic_soundex` generated **88.0% more candidates** in Test (3.77 cands/S1 vs 2.01 in Val) due to non-Latin Romanized name variations.
2. **Postal Code Collapse**: `method_a_postal_cname` yielded almost no candidates (0.0016 cands/S1) due to postal code scarcity in French and international records.
3. **High Duplicate Overlap**: 35.81% of test candidates are generated by multiple blocking rules, proving that individual rules provide effective overlapping safety nets.
